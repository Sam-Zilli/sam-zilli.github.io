Python Precedence & Evaluation

How Python Evaluates Expressions

Python does not read arithmetic left to right. It follows operator precedence and associativity, evaluates sub-expressions, and only then combines results. Use the tabs below to break down examples, step through evaluation, review the hierarchy, and test yourself.

Spotlight Breakdown

Two classic expressions show why precedence matters. Expand each example for the full story.

Example 1: 3 + 4 * 2

Question: Without a calculator, what is 3 + 4 * 2?

result = 3 + 4 * 2 # What value lands in result?

Key idea: Multiplication (*) binds tighter than addition (+). Python evaluates 4 * 2 first to get 8, then computes 3 + 8.

Answer: 11 — not 14 (which would happen if addition ran first).

Example 2: (3 + 4) * 2

Question: How do parentheses change the outcome?

result = (3 + 4) * 2

Key idea: Parentheses force the grouped sub-expression to run before anything outside it. 3 + 4 becomes 7, then 7 * 2 yields 14.

Answer: 14 — the same numbers as Example 1, but grouping changes the result.

Step Visualizer

Click each step to see which part of the expression Python evaluates next.

Example 1: 3 + 4 * 2

3 + 4 * 2 → 3 + 8 → 11
Step 1: Python parses the whole expression 3 + 4 * 2. It knows both + and * are present and will apply precedence rules before producing a single value.
Step 2: Because * has higher precedence than +, the sub-expression 4 * 2 is evaluated first (highlighted). Addition waits its turn.
Step 3: 4 * 2 becomes 8. The expression is now effectively 3 + 8.
Step 4: Addition runs: 3 + 8 equals 11. Evaluation is complete.

Example 2: (3 + 4) * 2

(3 + 4) * 2 → 7 * 2 → 14
Step 1: The expression (3 + 4) * 2 includes parentheses. Grouping is the strongest influence on order here.
Step 2: Everything inside (3 + 4) is evaluated before the multiplication by 2.
Step 3: The grouped sum is 7. Python now evaluates 7 * 2.
Step 4: 7 * 2 is 14. That is the final result.

Precedence Hierarchy

Higher rows bind tighter (evaluated earlier). When in doubt, use parentheses — they always win.

Precedence (high → low) Operators / constructs Notes
1 (tightest) ( ) — grouping, calls, subscripts Parentheses override default order
2 ** Exponentiation; right-associative
3 +x, -x, ~x Unary operators
4 *, /, //, % Multiply, true divide, floor divide, modulo
5 +, - Binary addition and subtraction
6 <, <=, >, >=, ==, != Comparisons (chained comparisons are special)
7 not Logical not
8 and Logical and
9 (loosest) or Logical or
